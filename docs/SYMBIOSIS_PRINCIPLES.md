# Symbiosis Principles

## 1. Goal

Thoughtforge should enable the strongest practical form of human-AI symbiosis available without direct neural interfaces.

That means the system should reduce the need for users to translate themselves into prompts over and over again.

## 2. What Symbiosis Means Here

The system should maintain a live, inspectable model of:

- what the user is trying to do
- what the user believes
- what constraints are real
- what has changed
- what deserves attention now
- what the agent may do next

## 3. Core Principles

### 3.1 Memory Without Repetition

The user should not need to restate the same goals, constraints, or background context every time.

### 3.2 Live State Over Static Documents

The system should understand current commitments, active focus, and changing reality, not just store notes.

### 3.3 Inspectable Intelligence

Every important inference, recommendation, or action should be explainable and grounded in evidence.

### 3.4 Bounded Autonomy

The system should know when to ask, when to draft, when to wait, and when it is allowed to act.

### 3.5 Respect for Human Agency

The system should make the user more effective, not less in control.

## 4. Product Implications

- notes are evidence, not the entire product
- context objects must be first-class
- the system needs live models, not just static metadata
- the context daemon is a core subsystem
- the context compiler is a core subsystem
- policy and delegation are core subsystems

## 5. Failure Modes to Avoid

- becoming just another chat UI
- becoming a slower Obsidian
- becoming an opaque surveillance tool
- becoming over-automated before trust is earned
- becoming dependent on remote providers for core value

## 6. Success Test

Thoughtforge is on the right path when a user can stop chatting for most daily work and still have the agent understand what matters, what changed, what to do next, and what not to do.
